# 本地可用版本交付说明

日期：2026-09-21

## 已确认的界面与范围

在用户认可原型后，采用默认的橙白进度工作台作为正式入口。移除全景和专注档案两个备选布局、底部切换器与内存示例数据，保留按阶段对齐和节点编辑交互。旧原型地址重定向到根页面。

第一版范围为个人本机使用、手动录入、自定义线性流程、记录时间。提醒、飞书导入或同步、多人账户、云服务仍不在本次范围内。

## 实现取舍

- 保留原生 JavaScript 模块，不为已有界面引入 React 和构建工具。页面渲染、交互、业务规则、存储与 HTTP 服务分文件维护。
- SQLite 是正式存储；一次记录修改及其历史在同一事务中提交。使用 WAL 和 FULL 同步模式。
- 每份投递的有序节点与历史作为 JSON 文档存入 SQLite，适合单人少量记录；字段和备份在服务端进行完整验证。
- 使用全工作区修订标识检查旧页面提交。即使修改的是不同记录，过期页面也须重新读取数据，这是为了避免恢复和其他页面更新造成静默覆盖。
- 前端只在服务端确认成功后更新列表；保存失败保留表单内容。网络中断导致结果未知时，需要重新连接检查记录。
- 数据库迁移使用 `user_version`，高于当前程序支持版本的数据库拒绝打开。
- Node.js 使用本机已有的 24.14.1，SQLite 通过内置模块访问；不需要安装第三方依赖。参见 [Node.js SQLite 文档](https://nodejs.org/api/sqlite.html)。

## 备份与恢复

导出格式为版本 1 的 `winoffer-backup` JSON，包含全部投递、节点和历史。恢复前完整验证全部内容，并让用户确认记录数和替换范围。

恢复在一个写事务中进行：先检查修订标识，写入并落盘恢复前的完整 JSON 副本，再替换投递并提交。验证失败、备份失败、数据库写入失败均不会丢失旧记录。自动副本可通过页面再次选择恢复。

移除流程节点前提示已有内容的影响，保存后可撤销最近一次流程调整。操作历史保留旧流程快照；Offer 节点被撤销移除时，原接受决定也会恢复。

## HR 面与待办快捷筛选（2026-09-22）

HR 面加入默认流程，位于三面和 Offer 之间。持久化标识保持稳定：Offer 仍为 7，HR 面为 8；显示及默认流程顺序由 `STAGE_ORDER` 定义，不能按标识大小排序。

记录使用 `workflowVersion: 2` 标记此次升级，JSON 备份格式仍为版本 1。服务启动时先保存 `before-hr-stage-…` 原始备份，再以事务补齐旧记录和流程撤销快照，保持原更新时间。旧自定义 HR 面复用原节点标识和内容；已满 64 节点的自定义流程保持原样。恢复旧备份同样升级，升级后手动删除 HR 面不会被再次补回。

快捷筛选沿用待完成规则，仅匹配当前有效节点的 `scheduled` 或旧 `active` 状态，排除待结果、已结束以及过时的早期安排。待面试包含 AI 面试、一面、二面、三面和 HR 面。快捷按钮单选，再次点击取消，点击时回到第一页并重置工作区类别与阶段条件，保留关键词、城市和企业性质。

验证：51 项自动测试与语法检查通过；浏览器验证筛选切换、组合条件、分页重置、HR 面保存及 390–2560 像素的六种屏幕宽度。

## 默认按节点时间排序（2026-09-22）

排序下拉第一项与初始默认值改为「节点时间最近」，保留最近更新、投递时间与公司名称。排序先于分页，新增投递后也使用此默认值。

按实际节点顺序选择最后一个非跳过且已填写状态或安排/截止日期的节点，包括 HR 面、自定义节点及预填日期的节点。使用该节点的统一日期和具体时间，比较与浏览器当前本地时间的绝对距离；仅填写日期时视为本地整天，今天的距离为零。不借用更早节点的日期，也不使用实际完成日期。缺少日期的记录排在有日期的记录后方，再按最近更新排序；距离相同也按最近更新排序。每次重新渲染或回到页面时重新计算，排序不会更改投递记录或更新时间。

## 合并节点日期（2026-09-22）

节点编辑只提供「安排/截止日期」与可选「具体时间」，移除独立截止日期、截止时间及实际完成日期输入。`nodeSchedule` 统一解析日期：优先原安排日期，否则使用旧截止日期及对应的时间；编辑、进度线、详情、状态摘要和节点时间排序使用同一规则。若旧备份两种日期均有值，优先原安排日期，不混用另一组时间。

保存或清除进度时，日期写入 `date/time`，同时清空旧 `deadline/deadlineTime`，保证清空日期后旧截止日期不会再次显示。既有记录和旧备份无需批量迁移；未编辑的历史字段仍可完整导出，实际完成日期保留为兼容字段但不参与界面或排序。

验证：60 项自动测试通过；浏览器验证旧日期回填、修改保存、刷新、清空、时间校验、清除进度以及桌面和手机布局。
