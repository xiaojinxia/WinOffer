# 邮件助手：配置与使用

## 配置

首次安装执行 `npm ci`。把根目录 `.env.example` 复制为 `.env.local`，使用本地文本编辑器填写：

```dotenv
DEEPSEEK_API_KEY=你的API密钥
DEEPSEEK_MODEL=deepseek-flash
QQ_EMAIL=你的QQ邮箱地址
QQ_AUTH_CODE=QQ邮箱生成的IMAP授权码
WINOFFER_AGENT_DEMO=false
```

QQ 网页邮箱中开启 IMAP/SMTP 服务，生成授权码；不要填写 QQ 登录密码。该文件已被 Git 忽略，但仍是本地明文，请勿分享。重启服务后生效。环境变量也可配置这些值；API 密钥不进入浏览器或 JSON 投递备份。

默认模型依据实施时的 [DeepSeek 官方模型页](https://api-docs.deepseek.com/quick_start/pricing/) 设为 `deepseek-flash`，可根据账号可用模型修改。接口固定为官方 HTTPS 地址，不支持在聊天或邮件中切换代理地址。

## 正常使用

1. `npm start`，在顶部点击“邮件助手”。
2. 展开连接说明，分别测试 QQ 和 DeepSeek。模型探测可能产生少量用量；不会发送邮件。
3. 选择同步日期范围与上限，点击同步。已读、未读均读取，不改已读状态。
4. 需要分析时勾选数据发送授权。同步时可勾选“同步后分析”，也可先同步，再勾选具体邮件分析。
5. 选择建议，核对原文、公司岗位、轮次、时间和时区。需要时更改目标及字段，勾选已核对，再生成预览。
6. 阅读全部差异，包括前序跳过、简历推进及时间清空，点击确认。只有此时才写入投递。
7. 页面提示版本冲突时重新检查并生成预览；不要把旧预览当成已保存。确认请求超时后会查询建议状态，重试相同确认不会重复写入。

只有一个明确候选且无缺失项时可生成预览；多个候选需手工关联。没有对应投递时先回工作台新建。当前提取没有附件解析，未知轮次、日期或取消通知需人工处理。

## 对话与草稿

先勾选本地邮件，再输入“整理这些邮件的面试安排并提出更新”等任务。Agent 可以多轮调用查询、分析和草稿工具，不能调用确认、删除或发送接口。每个任务最多 8 次模型调用、20 次工具调用、5 分钟；达到限额会保留已完成结果，缩小范围后继续。

“起草回复”为首封选中邮件生成本地正文，也可以在对话中说明回复要求。可编辑并复制正文自行发送。当前没有保存到 QQ 草稿箱或 SMTP 发信功能。

## 数据与限制

- 选中正文和必要的投递摘要会发送给 DeepSeek；不会默认把整个邮箱和整库发送给模型。
- 同一时间只执行一个 Agent 任务。页面关闭不影响服务进程中的任务；关闭服务会中断，重启后可重新发起，已入库邮件与建议保留。
- 同步按指定日期范围查询 UID，只下载本地尚未保存的邮件。单批最多 100 封；范围内还有剩余时显示数量。可扩大日期范围补扫，不提供后台轮询。
- 正文读取最多 64 KiB，模型输入最多 12,000 字符，截断时要求人工核对；附件只展示名称。当前不自动合并不同邮件的改期事件，用户要检查新旧通知与已有安排。
- 同一邮件一个建议包，可包含多个节点操作。已应用的包不会再次应用；如需纠正使用工作台。尚不支持重新运行模型替换已有建议，已有建议可手动修改和重新预览。
- 投递历史保存来源主题和建议 ID，完整差异及证据在 Agent 审计中。已应用邮件的直接回复可辅助关联同一投递；出现公司、岗位或申请编号冲突时重新选择，暂不提供公司别名学习。
- 正文启动时按 90 天清理，待补充/待确认/失效建议所需正文保留；也可点击清理缓存。已应用事件的最小证据保留。清理不会删除 QQ 邮箱中的原邮件。
- 现有 JSON 备份只包含投递及历史中的来源摘要，不包含邮箱缓存、建议、任务和草稿。完整迁移请停止服务后复制整个 `data/`，不要只复制运行中的主数据库文件。
- 首次升级数据库会在 `data/backups/before-agent-*.sqlite` 保存一致性副本。旧程序不能打开升级后的库；回退前停服务并恢复旧副本，之后的新增数据不会自动合并。

## 不用真实凭据体验

设置 `WINOFFER_AGENT_DEMO=true` 后会显示“加载演示邮件”。此按钮只产生一封明确标识的模拟邮件与待关联建议，不连接邮箱或模型，不自动创建投递。可以在**独立测试数据目录**建立“演示公司”的投递，选择该建议完成预览与确认。

演示开关只是开放演示入口；其他“同步 QQ”“DeepSeek 分析”按钮仍是显式真实操作，需要相应配置。建议在独立目录体验，避免把演示安排确认到真实投递。

真实 QQ 连接和 DeepSeek 调用需在填入个人凭据后验证；交付时的测试使用隔离数据库、模拟模型/邮件及本地浏览器，没有读取个人邮箱或产生真实模型调用。
