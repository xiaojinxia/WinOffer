# WinOffer

橙白配色的个人求职记录系统，在本机浏览器中使用，记录保存在本地 SQLite 数据库中。

## 日常启动

电脑需要 **Node.js 24.14 或更新的 24.x 版本**（已在 24.14.1 验证）。无需安装 npm 依赖。

Windows 双击项目目录中的 **`start.cmd`**；macOS 双击 **`start.command`**。Mac 若无法直接打开，可在“终端”中输入 `bash `（末尾留一个空格），将 `start.command` 拖入终端，再按回车。也可以在项目目录运行：

```powershell
npm start
```

启动后自动打开 [求职工作台](http://127.0.0.1:4173/)。保持服务窗口运行即可使用，结束使用后可关闭窗口或按 Ctrl+C。关闭页面、停止服务、重启电脑均不会删除已经保存的记录；重启电脑后再次运行启动脚本即可。

Mac 与 Windows 使用相同的 JSON 备份格式。分享个人记录时，可下载备份文件，让接收方在自己的系统中恢复；恢复会替换接收方已有记录，之后双方的数据独立保存。

只启动服务、不打开浏览器：`npm run dev`。旧的 `start-prototype.ps1` 和 `/prototype` 地址会进入当前版本。

## 已实现的功能

- 每条投递一条进度线，默认八个阶段尽量按列对齐；自定义顺序按真实流程展示。
- 新建和编辑投递，记录公司、岗位、多个城市、企业性质、部门、招聘批次、申请编号、招聘链接、薪资和备注。
- 岗位可留空，提供 AI应用、Java后端、研发、通用、未知五种选择；已有其他岗位文字会保留。页面按 2027 招聘周期展示，默认放大至 110%。
- 节点可选待完成、待结果、已通过、未通过、已跳过。尚未设置进度的节点保持空白；旧“已安排”和“进行中”节点统一显示为“待完成”，兼容已有数据与备份。
- 简历仍为“待筛选”时，只要后续节点的状态不再是“未开始”（包括已跳过），简历就会自动标记为“已通过”。不覆盖手动记录的未通过等状态，也不补填日期。已有记录在服务启动时更新并保留更新前备份，恢复旧备份时同样应用此规则。
- 记录安排日期、具体时间、截止日期与时间、实际完成日期、地点、会议链接和阶段备注。
- 增删和调整流程节点顺序、恢复被移除的标准阶段、撤销最近一次流程调整。
- 公司/岗位/城市搜索，企业性质、城市、当前阶段和结果筛选，以及排序。
- 列表每页显示 6 条，按窗口剩余高度均分行高，末页保持相同行高；较小窗口保留滚动以保证内容可读。底部支持上一页、下一页与页码跳转；搜索、筛选和排序后回到第一页，末页记录删空时自动返回有效页。
- 记录列表隐藏竖向滚动条，较小窗口中仍可使用滚轮或触控板滚动，表头保持可见；横向滚动时表头与进度列对齐，分页按钮位于列表外。
- 主动结束和恢复投递，记录 Offer 待决定、已接受或已婉拒。
- 点击公司名称进入详情，底部可删除整条投递；确认后移除流程、备注与历史，列表和统计即时更新。删除不能直接撤销，请按需提前导出备份。
- 持久化操作历史，保存失败时保留编辑内容；旧页面提交会提示冲突，避免覆盖其他页面的更新。
- JSON 完整备份、恢复前预览与确认、恢复前自动备份及找回。

首次打开为空工作区。原型中的公司进度是虚构示例，不会写入正式数据库。当前版本仅供单人本机使用，按已确认范围不包含飞书导入、跨设备同步或时间提醒。

## 保存与备份

数据库默认位于项目目录的 **`data/winoffer.sqlite`**。`data/` 已加入 `.gitignore`，不会作为源代码提交。

页面出现“已保存”后，修改已写入数据库。尚未点击保存的编辑内容会在关闭或刷新时提示确认。

右上角 **备份与恢复 → 下载备份文件** 可以导出全部记录、节点、时间、备注和历史。可将 JSON 文件保存到另一块磁盘或自己的备份目录。

恢复会**替换全部记录，不会合并**。需要先选择文件、检查记录数并勾选确认。系统会在 `data/backups/` 自动保留恢复前的数据；若想撤回恢复，可在同一面板中选择“恢复前自动备份”。无效文件、过期页面、无法写入自动备份或数据库写入失败，都不会覆盖当前数据。

SQLite 运行时可能同时出现 `winoffer.sqlite-wal` 和 `winoffer.sqlite-shm` 文件，这是数据库的工作文件。需要复制整个数据目录时，先关闭服务；日常备份建议使用页面的导出功能。不要在服务运行时单独复制或移走数据库文件。

## 开发与检查

```powershell
npm run check
npm test
```

测试使用 `.preview/` 下独立临时数据库，不会操作真实 `data/`。测试涵盖状态计算、持久化、重复投递、编辑冲突、导出恢复、恢复失败回滚、输入验证和本地 HTTP 接口。

源码结构：

```text
public/          工作台、编辑面板、交互和橙白样式
shared/model.js  状态计算、输入验证和流程修改规则
server/          本地 HTTP 服务、SQLite 存储、备份恢复
test/            业务规则、数据库和 API 检查
data/            真实投递数据，首次启动自动创建
```

前端采用原生 JavaScript 模块，沿用已认可的页面交互，没有构建或在线资源依赖。数据库使用当前 Node.js 自带的 `node:sqlite`；该版本运行时会显示实验性 API 提示，不影响已验证的本地保存功能。

如默认端口被其他程序占用，可设置 `PORT` 后启动。若要自定义数据目录，可在启动前设置 `WINOFFER_DATA_DIR` 为绝对路径；使用一个新目录会打开一个独立工作区，不会自动迁移旧数据。
