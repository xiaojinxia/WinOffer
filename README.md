# WinOffer

**让每一步，都有迹可循。**

WinOffer 是一个在本机浏览器中使用的个人求职工作台。每份投递对应一条招聘进度线，把公司信息、笔试面试安排、阶段反馈和 Offer 决定集中记录，方便查看和跟进。

数据保存在本地 SQLite 数据库中，无需注册账号；页面不依赖在线资源，支持离线使用。项目使用原生 JavaScript 和 Node.js 内置模块，无需安装第三方依赖或执行构建。

## 主要功能

- **投递管理**：记录公司、岗位、多城市、企业性质、招聘批次、投递日期、招聘链接、薪资和备注；同一公司可建立多份独立投递。
- **招聘进度线**：默认包含简历、测评、笔试、各轮面试及 Offer，点击节点即可更新状态、安排/截止日期、具体时间、地点、会议链接和阶段备注。
- **自定义流程**：按每家公司的实际流程增删、跳过和调整节点顺序，也可恢复被移除的标准阶段。
- **搜索与筛选**：按公司、岗位或城市搜索，结合企业性质、城市、当前阶段及工作区分类筛选；提供「待测评」「待笔试」「待面试」快捷入口。
- **结果与历史**：管理 Offer 的待决定、已接受和已婉拒状态，主动结束或恢复投递，查看操作历史。
- **备份与恢复**：导出完整 JSON 备份，恢复前预览并确认，自动保留替换前的数据，支持在 Windows 和 macOS 之间迁移记录。

当前版本面向单人本机使用，不提供多人账户、云端或跨设备自动同步、飞书导入及时间提醒。

## 快速开始

### 环境要求

- **Node.js 24.14 或更新的 24.x 版本**，即 `>=24.14.0 <25`。
- Windows 或 macOS，以及可用的浏览器。

可运行 `node --version` 检查版本。无需运行 `npm install`。

### 启动工作台

下载或克隆项目后，在项目目录中运行：

```sh
npm start
```

也可以直接双击启动脚本：

| 系统 | 启动文件 |
| --- | --- |
| Windows | `start.cmd` |
| macOS | `start.command` |

macOS 若无法直接打开脚本，在终端输入 `bash `（末尾留一个空格），将 `start.command` 拖入终端，再按回车。

启动后会自动打开 [本地工作台](http://127.0.0.1:4173/)。如果浏览器没有打开，可手动访问该地址。首次使用新数据目录时，工作区为空。

使用期间保持服务窗口运行；结束后按 `Ctrl+C` 停止。已经保存的记录会保留，重启电脑后再次启动即可继续使用。只启动服务、不自动打开浏览器时，运行 `npm run dev`。

## 使用方式

### 记录一份投递

1. 点击「新建投递」，填写公司及相关信息。岗位可以留空；同公司不同岗位、不同批次可分别记录。
2. 点击进度线上的节点，选择状态并填写安排。面试结束但尚未收到反馈时，可先标记「待结果」。
3. 点击公司名称查看详情，编辑基本信息、调整流程、查看历史或管理 Offer 决定。

默认流程为：

```text
投递简历 → 测评 → AI 面试 → 笔试 → 一面 → 二面 → 三面 → HR 面 → Offer
```

节点支持「待完成」「待结果」「已通过」「未通过」「已跳过」五种状态。尚未填写的节点保持未开始；误填时可用「清除进度」重置状态，保留时间和备注。

流程与进度遵循以下规则：

- 将某个节点设置为非「未开始」状态时，它之前尚未开始的节点会自动标记为「已跳过」，简历节点除外；已填写的其他状态保持不变。
- 简历仍为「待筛选」时，只要后续节点有进度（包括已跳过），简历就会自动标记为「已通过」。仅填写时间或备注不会触发，也不会覆盖手动记录的其他简历状态或补填日期。
- 流程调整只影响当前投递。最近一次操作是流程调整时，可在详情中撤销；后续再做其他修改后，该撤销入口不再可用。

主动结束的投递可以在详情中恢复。删除整条投递会同时删除流程、备注和历史，**无法直接撤销**，需要保留时请先导出备份。

### 查找需要跟进的记录

「待测评」「待笔试」「待面试」只显示**当前阶段为待完成**的投递，不包含待结果或已结束的记录。「待面试」覆盖 AI 面试、一面、二面、三面和 HR 面。快捷筛选单选，再次点击取消，可叠加关键词、城市和企业性质条件。

列表默认按「节点时间最近」排序：按实际流程取最后一个已填写进度或安排/截止日期的非跳过节点，再按该节点时间距现在的远近排列，过去和未来的日期都会参与。只填日期时按本地整天计算，今天优先；该节点没有日期时排在后面，按最近更新排序，时间距离相同也按最近更新排序。也可切换为最近更新、投递时间或公司名称排序。

每页显示 6 条记录，支持翻页和页码跳转；在节点列表区域向下滚动鼠标滚轮可翻到下一页，向上滚动返回上一页。窗口较矮时先滚动当前页内容，到底部或顶部后继续滚动才翻页；连续滚动一次只翻一页，稍停后可继续翻页。搜索、筛选或排序后回到第一页。

## 数据保存与备份

数据库默认位于 `data/winoffer.sqlite`，首次启动时自动创建。`data/` 已加入 `.gitignore`，不会随源代码提交。页面提示保存成功，表示修改已写入数据库；关闭页面、停止服务或重启电脑都不会清除已保存的记录。

保存失败时，页面会保留编辑内容。多个页面同时操作时，过期页面的提交会提示冲突，避免覆盖已经保存的更新。

在右上角「备份与恢复」中操作：

1. **导出**：点击「下载备份文件」，保存包含全部投递、流程节点、时间、备注和历史的 JSON 文件。
2. **恢复**：选择 WinOffer 导出的备份，核对预览中的记录数，勾选确认后恢复。**恢复会替换全部当前记录，不会合并。**
3. **找回恢复前的数据**：在同一面板的「自动备份」中选择恢复前的副本，检查后再次恢复。

恢复前的副本保存在 `data/backups/`。旧记录需要升级 HR 面流程或更新简历状态时，也会先保留自动备份。备份校验失败、页面版本过期、自动备份写入失败或恢复写入失败时，不会覆盖现有数据。

换电脑时，在原电脑导出 JSON，再在新电脑启动 WinOffer 并恢复即可。Windows 与 macOS 使用相同的备份格式，迁移后两边的数据独立保存。

建议将导出的备份另存到其他磁盘或备份目录。若需直接复制整个 `data/`，请先停止服务：SQLite 运行时可能同时使用 `winoffer.sqlite-wal` 和 `winoffer.sqlite-shm`，不要在服务运行时单独复制或移走数据库文件。

## 可选配置

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `PORT` | `4173` | 修改本地服务端口 |
| `WINOFFER_DATA_DIR` | 项目下的 `data/` | 指定数据目录，建议使用绝对路径 |

例如，将端口改为 `4180`：

Windows PowerShell：

```powershell
$env:PORT = "4180"
npm start
```

macOS 终端：

```sh
PORT=4180 npm start
```

自定义数据目录时，在启动前设置 `WINOFFER_DATA_DIR`，数据库和自动备份都会保存在该目录。指定一个新目录会打开独立工作区，**不会自动迁移原有数据**，可使用 JSON 备份迁移。

服务仅监听本机 `127.0.0.1`。默认端口被其他程序占用时，可按上例更换端口。

## 开发与检查

| 命令 | 作用 |
| --- | --- |
| `npm start` | 启动本地服务并打开浏览器 |
| `npm run dev` | 仅启动服务，不包含自动重载 |
| `npm run check` | 检查主要 JavaScript 文件语法 |
| `npm test` | 运行 Node.js 内置测试 |

测试使用 `.preview/` 中的独立临时数据库，不会操作真实 `data/`。覆盖业务状态、节点时间排序、数据持久化、编辑冲突、删除、备份恢复、失败回滚和本地 HTTP 接口。

```text
public/                 页面、交互、样式与静态资源
shared/model.js         状态计算、输入校验与流程规则
server/index.js         启动入口、端口与数据目录配置
server/http.js          本地 HTTP 服务与 API
server/store.js         SQLite 存储、事务与备份恢复
test/                   业务规则、存储与接口测试
docs/                   产品计划与实现记录
data/                   本地用户数据，启动时自动创建
```

前端使用原生 JavaScript 模块，后端使用 Node.js 内置 HTTP 服务和 `node:sqlite`。启动时可能出现 SQLite 实验性 API 提示。旧入口 `start-prototype.ps1` 和 `/prototype` 仍会进入当前工作台。

更多背景见 [产品计划](docs/product-plan.md) 与 [交付说明](docs/implementation.md)。
